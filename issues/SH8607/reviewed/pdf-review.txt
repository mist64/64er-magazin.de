# 2. p161 IS TYPE ON A GREY TINT PANEL  -> BILEVEL_THRESHOLD=28% (SETTLED)
# ---------------------------------------------------------------------------
# Owner: "p161 is too dark, discuss." then "p161: lighter?"
#
# Tabelle 2, the VIC register table: every other row is a grey screen carrying
# dark type -- low contrast by design.  At the fixed 35 % cutoff the screen
# shatters into a hard checkerboard and the numerals come through as blobs
# with the screen punched through them; "53249" is barely a number.
#
# MEASURED: p161 is the heaviest bilevel page in the issue -- JBIG2 ratio 20 %
# against 4-7 % for its neighbours, 30.5 % of the page black (3rd highest, and
# the two above it are the cover and a full-bleed black ad).  Of the other 175
# bilevel pages NONE has the same construction: p110 and p117 score high on
# tint area but those are a screen dump and a product photo, the accepted cost
# (r006, "a crushed halftone is a known, accepted cost").
#
# Whole-page black at each cutoff, p161 / issue mean:
#   35 %  30.5 / 14.3     28 %  21.1 / 13.2
#   25 %  18.1 / 12.6     20 %  13.6 / 11.4
# Ordinary type is INSENSITIVE over that range -- body text on p003 and the
# Impressum fine print on p178 are indistinguishable at 35 %, 25 % and 20 %,
# and p123's 8-point listing is marginally cleaner at 25 %.  What a lighter
# cutoff thins is SCREENS, not type: the pages that lose most from 35 % to
# 25 % are exactly the tint-panel pages (161, 001, 027, 118, 009, 100, 067).
#
# Options put to the owner: ship as-is / lighter global cutoff / FORCE_CONTONE
# ="161" at 150 dpi.  NOT re-screening -- owner, "no re-screen!!"
#
# RULED: the owner looked at the full page at 35 / 28 / 25 / 20 % and at the
# 150 dpi contone, and said "28 is good", then "25 too".  SH8607 SHIPS AT 28 %
# -- the value he named first and the smaller step away from the 35 % the rest
# of the archive carries.  Verified in the delivered PDF BY PIXELS, not by
# trusting the cache: p161 is 21.84 % black, against 21.06 % for a fresh 28 %
# threshold of a4600/161.png and 30.51 % for 35 %.  The 0.8-point gap is
# jbig2enc's lossy coding.
#
# THE COST WAS MEASURED BEFORE IT WAS TAKEN, AND THE FIRST NUMBER WAS A TRAP.
# Type on white ground (16x16 blocks whose own mean is > 215, so no screen and
# no photo) loses 19 % of its ink pixels at 28 % and 27 % at 25 %.  That reads
# alarming and is not: it is the grey rim of every glyph, not the glyph.  On
# p177, the worst page by that measure, the type is solid and unbroken at 35,
# 28, 25 AND 20 % -- no stroke breaks, no glyph drops.  An ink-count is a proxy
# for edge erosion, not for damage; the LOOK is the decision.
#
# The 35 % build is kept at <tmp>/64er_Sonderheft_1986-07.t35.pdf.
# 28 % is NOT proposed as the archive default on one issue's evidence.
