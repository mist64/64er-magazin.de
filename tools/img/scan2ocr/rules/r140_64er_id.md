# 140 — Fill `64er.id` with a short lowercase slug per article

**Applies to:** all — every article needs a slug. The recurring-rubric slug list is a convenience for whichever of those rubrics the issue actually has.

**Goal:** replace each article's `<meta name="64er.id" content="XXX<N>">`
placeholder (left by the split step) with a real short lowercase slug
the generator uses for URLs (`/<issue>/<id>.html`), permalinks, and
cross-issue links.

This step has no automatable transformation — the slug is an editorial
decision per article — but the mapping it produces is mechanical to
apply.

## Slug format

- Characters allowed: `a-z`, `0-9`, `-`. Hyphens separate words. No
  spaces, no capitals, no punctuation.
- The project does carry slugs with German umlauts (`dfü`,
  `hexenküche2`) and `_` for older inherited mappings, so accept those
  when matching an existing precedent — but prefer ASCII-hyphen for new
  slugs.
- Soft cap: 24 characters. Longer is allowed when no shorter form is
  recognisable.
- Must be unique within `issues/<YYMM>/`. Across issues, recurring
  rubrics (Aktuelles, Leserforum, Editorial, Fehlerteufelchen,
  Vorschau, CP/M-Ecke, Tips für Einsteiger/Profis/C 16, …) share the
  **same** slug from issue to issue — that's how cross-issue links to
  "the column" stay stable.

  **AND SO DOES A SUBJECT, not only a named column.** This is the part that
  gets missed: a later article about the same program, product or course
  takes the earlier article's slug. MEASURED over the corpus — 214 of 1093
  ids are reused across issues, and only 11 of those are recurring rubrics.
  The other **203 are subject threads**: `checksummer` over 20 issues,
  `assembler` 19, `memory_map` 18, `mse` 13, `pascal` 8, `dfü` 8. Reuse is
  the dominant mechanism here, not an accident to be avoided.

  A distinct slug is not "the safe direction". Nothing collides — the URL is
  `/<issue>/<id>.html`, so two issues may carry the same id — and the only
  thing a distinct slug achieves is cutting the thread. 8611 proposed
  `prodisc-ergaenzungen` and `prolog-64` where the corpus has `prodisc`
  (8606/48) and `prolog` (8603/140), for articles that are explicitly the
  same subject: *"Das Diskettenverwaltungsprogramm »ProDisc« **aus Ausgabe
  6/86** wurde von vielen Lesern abgetippt"*, and a Prolog 64 review
  following a Prolog 64 review.

  **The test is the article's own words.** An article that names an earlier
  issue is telling you which thread it belongs to; 20 articles in the 86xx
  run do exactly that, and they reuse the subject's slug.

  **A COURSE SPLIT OVER SEVERAL ARTICLES STILL HAS ONE SLUG.** "Keep the
  series slug stable" assumed one article per part. SH8604's course runs over
  7 articles and continues a one-article course (`kurs`, SH8502/7): all 7 take
  `kurs`, because the thread is the course and not the instalment. Uniqueness
  is **within the issue** for `64er.id`-as-filename only where the generator
  needs it; a shared subject slug across an issue's own parts is the same
  mechanism as across issues.

  **AND THE SLUG IS THIS STEP'S CALL, NEVER AN OWNER QUESTION.** SH8604
  carried `kurs` and `kleiner-hobbit` to the owner list twice after control had
  already said a shared slug is not a defect. A judgement this rule assigns to
  this step is this step's to make; put it in the report as a decision, with
  the evidence below, not as a question.

## How to pick the slug

1. **Recurring rubric?** Look up the slug used in the previous issue
   for the same column and use it. The recurring slugs include
   `editorial`, `aktuelles`, `leserforum`, `fehlerteufelchen`,
   `vorschau`, `extra`, `cpm`, `dfü`, `pascal`, `assembler`,
   `tips_einsteiger`, `tips_profis`, `tips_c16`, `tips_vizawrite`,
   `superbase`, `anwendung_des_monats`, `listing_des_monats`,
   `knobeleien`, `c128-reisebericht`, `hypra-basic`, `profi-grafik`.
2. **Program / product name?** Use the program's name lowercased and
   hyphenated (e.g. PYRAMIDE → `pyramide`, Vectors → `vectors`,
   Maintext 64 → `maintext`, Seikosha MP-1300 AI → `mp1300`, CPA-80X
   → `cpa80x`).
3. **Topic-leading title?** Use the topical keyword(s) (e.g.
   "Selbstbau Das richtige Kabel zum Monitor" → `monitorkabel`).
4. **Disambiguate** when a natural slug collides with a previous
   article (or with another article in the same issue). Append a
   suffix like `-2`, `-c128`, `-grafik` only after exhausting the
   topic-narrowing options.

**On a Sonderheft the opening piece is `vorwort`, not `editorial`** — measured,
`vorwort` appears in **8 of 16 Sonderhefte and 0 of 33 monthlies**, and
`editorial` in 33 of 33 monthlies and 2 Sonderhefte. `checksummer` (10 of 16),
`mse` (7) and `impressum` (11) recur on a Sonderheft too. Check 4 now carries
a per-series list and the measurements behind it; compare against the previous
issue of the SAME series, and treat a missing theme slug as expected.

The editorial slug should always be `editorial`, regardless of what
the editorial article's title actually reads.

## Procedure

For an issue with the placeholder `XXX0..XXX<N-1>` ids in place:

1. List every article and its title (or topical theme), grouped by
   rubric where applicable.
2. Draft the `{XXX<N> → slug}` mapping. For each article note: the
   article's `<title>`, the chosen slug, and (when not obvious) the
   reason — recurring-rubric match, program name, topic keyword,
   disambiguator.
3. Cross-check the mapping against the previous issue's slugs for
   every recurring rubric — they must match exactly.
4. Apply the mapping to `issues/<YYMM>/*.html`, replacing each file's
   single `<meta name="64er.id" content="XXX<N>">` line with
   `<meta name="64er.id" content="<slug>">`. Leave every other byte
   untouched.

## Verification

```bash
# SET THESE FIRST.  The snippet used to spell <YYMM>, <ID> and
# <PREV-SAME-SERIES> as placeholders and never bind them, so it was copied
# and run with the brackets intact.
: "${ISSUE:?set ISSUE, e.g. SH8604}"
: "${PREV:?set PREV to the previous issue of the same series AND machine}"

# 1. Every article has a non-empty, non-placeholder id:
for f in issues/$ISSUE/*.html; do
  v=$(grep -oE '<meta name="64er\.id" content="[^"]+"' "$f" | head -1 | sed -E 's/.*content="//;s/"$//')
  [ -z "$v" ] && echo "  empty: $f"
  [[ "$v" =~ ^XXX[0-9]+$ ]] && echo "  placeholder still: $f -> $v"
done

# 2. All ids in the issue are unique:
grep -hoE '<meta name="64er\.id" content="[^"]+"' issues/$ISSUE/*.html | \
  sort | uniq -c | awk '$1 > 1 { print "  dup:", $0 }'

# 3. Charset sanity (lowercase + digits + hyphen + the legacy
#    underscores/umlauts the project tolerates):
grep -hoE '<meta name="64er\.id" content="[^"]+"' issues/$ISSUE/*.html | \
  sed -E 's/.*content="//;s/"$//' | grep -nvE '^[a-z0-9äöüß_-]+$' | \
  head -5

# 4. Cross-issue recurring slugs intact.
#
# THE LIST IS PER SERIES, AND IT IS MEASURED.  The old one -- aktuelles,
# leserforum, editorial, fehlerteufelchen, vorschau, impressum, bücher, cpm --
# is monthly-shaped, so against a Sonderheft it passes trivially while missing
# the slugs that actually recur there.  Counted over 16 Sonderhefte and 33
# monthlies in the archive:
#
#   slug              SHefte  monthlies
#   impressum           11       33
#   checksummer         10       12
#   vorwort              8        0      <- never a monthly
#   mse                  7        7
#   bücher               3       26
#   editorial            2       33
#   vorschau             0       33
#   leserforum           0       33
#   fehlerteufelchen     0       23
#   aktuelles            0        8      <- barely recurs even monthly
#   cpm                  1        6      <- ditto
#   abtippen             0        1      <- not recurring at all
#
# So `aktuelles` and `cpm` leave the list (8 and 6 of 33 is not a rubric you
# can flag the absence of), `abtippen` never belonged, and a Sonderheft gets
# its own four.  `mse` does not recur on a C16/VC 20 issue at all, which is
# why a missing one is a look and not a failure.
# The series is read off the DIRECTORY NAME, so an issue not named SH… gets
# the monthly list and the check passes on the wrong slugs.  That is the same
# silent-pass failure as the PREV one above; it only bites a scratch copy.
if [ "${ISSUE#SH}" != "$ISSUE" ]; then
  SLUGS="impressum checksummer vorwort mse"
else
  SLUGS="leserforum editorial fehlerteufelchen vorschau impressum bücher"
fi
# AND COMPARE AGAINST THE PREVIOUS ISSUE OF THE SAME SERIES *AND MACHINE*.
# Comparing a Sonderheft against the preceding monthly, or against a
# differently themed Sonderheft, flags the theme: between SH8601 (C 128) and
# SH8602 (Tips & Tricks) it reported `bücher` and `cpm` missing, so "all four
# checks should pass" could not be met.
#
# "SAME SERIES" WAS STILL TOO WEAK, and it fails SILENTLY in the safe
# direction.  SH8604 (C 64) compared against SH8603 (C 16 / VC 20), which has
# no `mse` at all -- so `prev` was empty, the test short-circuited, and a
# MISSING MSE WOULD HAVE PASSED.  Pick the previous Sonderheft for the same
# MACHINE, and if there is none, say in the report that check 4 had nothing to
# compare against rather than reporting it clean.
for slug in $SLUGS; do
  prev=$(grep -lE '64er\.id" content="'"$slug"'"' issues/$PREV/*.html)
  curr=$(grep -lE '64er\.id" content="'"$slug"'"' issues/$ISSUE/*.html)
  [ -n "$prev" ] && [ -z "$curr" ] && echo "  missing recurring slug: $slug"
done
```

All four checks should pass. The cross-issue check matters most when
the issue has the same recurring rubrics — flag missing ones rather
than just silently picking a new slug.

## Check 4 CANNOT see a reprint, and a Sonderheft is mostly reprints

Check 4 compares against one previous issue of the series. **A Sonderheft
built from monthly reprints takes its ids from the monthly ORIGINALS**, which
are neither the previous Sonderheft nor the previous monthly: SH8603's eight
reprints come from 8501, 8410, 8411, 8505 (×3), 8506, 8507 and 8510. Nothing
in this step could have found that list — it took a text-overlap pass over
the whole corpus.

**r330 needs the same list**, and derives it independently with the same pass.
So the step that finds it records it, and both read the record:

```
issues/<ID>/reprints.txt     one line per reprint:
                             <this article's file>  <origin issue>/<origin id>
```

Write it at whichever step runs the overlap pass first, and note in LOG.md
which step that was. r330's Step 0 has the matching caveat: its ~0.5 overlap
threshold cannot see a merged reprint (SH8603's eight scored 0.05–0.26),
so the pass that builds this file is per-block, not per-article.

## Evidence-in-report requirement

A previous sub-agent on a different rule claimed verification it never
ran (the `internsiv` OCR regression). To make that failure mode
impossible here, every slug the sub-agent assigns must be backed by
**runnable verifier evidence pasted verbatim into the report**:

- For each recurring-rubric slug, paste the one-line
  `grep -l '64er.id" content="<slug>"' issues/<PREV>/*.html` output
  showing the previous issue used exactly the same slug for the same
  column.
- For each non-recurring slug (program/topic), paste the one-line
  body / `<title>` grep output that justifies the picked slug, e.g.
  ```
  grep -h '<title>' "issues/8607/73 Vectors.html" → "<title>Vectors</title>"  → slug: vectors
  ```
- For every issue-internal uniqueness check, paste the
  `sort | uniq -c | awk '$1>1'` line confirming the chosen slug
  is not already used.

**No verifier output, no claimed slug.** A slug reported without the
previous-issue grep (for recurring rubrics) or the title-derivation
line (for new slugs) is treated as a guess; the orchestrator will
re-dispatch. "Trust me, I matched the rubric" is never acceptable.

## Notes / things to watch

- Don't ship `XXX<N>` as a final id under any circumstances — the
  generator will accept it but every URL will look broken.
- Don't reuse the article's filename as a slug. Filenames are
  sanitised for the filesystem, not for URLs.
- For multi-part articles (e.g. "Pascal-Kurs Teil 4"), keep the
  series slug stable (`pascal`); the part number lives in the title
  and the `64er.toc_title`, not in the id.
- When in doubt between two reasonable slugs, prefer the one that
  matches the article's `<title>` more closely — a future reader
  doing a guess-the-URL is more likely to land on it.
- Slugs are case-sensitive everywhere they appear; "Pyramide" and
  "pyramide" are different URLs.
